# سیاست مدیریت نسخه و چرخه حیات

این سند نحوه مدیریت، پین کردن و ردیابی نسخه‌های کامپوننت‌ها در طول چرخه حیات آن‌ها در استک کلود-بومی را تعریف می‌کند.

## اصول پین کردن نسخه

1. **فقط نسخه دقیق** — تولید فقط از نسخه‌های دقیق استفاده می‌کند. تگ `latest`، ارجاع‌های Git شناور، و چارت‌های Helm بدون پین مجاز نیستند.
2. **استقرار مبتنی بر Digest** — ایمیج‌های کانتینر هر جا که پلتفرم پشتیبانی کند، با digest استقرار می‌یابند.
3. **منبع واحد حقیقت** — هر پین یک ردیف در `compatibility/version-matrix.md` با URL منبع و تاریخ بررسی دارد.
4. **بامپ نسخه اتمیک** — بامپ نسخه یک MR واحد است که ماتریس نسخه، ماتریس آرتیفکت، و راهنمای کامپوننت را همزمان به‌روزرسانی می‌کند.
5. **سازگاری اول** — ارتقای یک کامپوننت به نسخه‌ای که در ماتریس نسخه نیست، نیازمند عبور از تست‌های سازگاری در جدول «محدودیت‌های سازگاری کامپوننت‌به‌کامپوننت» است.

## دسته‌بندی نسخه‌ها

| دسته | توضیح | مثال |
|---|---|---|
| **VERIFIED** | از منبع رسمی در تاریخ بررسی خوانده شده؛ منبع لینک شده | `v1.21.2` |
| **PINNED** | نسخه دقیقی که این پلتفرم استقرار می‌دهد (انتخاب شده از مجموعه VERIFIED) | `v1.21.2` |
| **UNVERIFIED** | تأیید نشده. رویه تأیید بیان شده؛ تا تأیید نشود در استقرار استفاده نشود | `v1.22.0` |
| **CANDIDATE** | برای ادوات آینده ارزیابی شده، هنوز پین نشده | `v0.162.0` |
| **RETIRED** | دیگر پشتیبانی نمی‌شود؛ استفاده نکنید | `v1.15.3` |

## ردیابی نسخه کامپوننت‌ها

### کوبرنتیز و چرخه حیات کلاستر
- **Kubespray** ابزار اصلی استقرار کوبرنتیز است
- پنج ریلیز Kubespray به صورت موازی پشتیبانی می‌شوند (ADR-0026)
- هر ریلیز نسخه‌های پین شده کامپوننت‌های خاص خود را دارد
- نسخه کوبرنتیز باید در بازه پشتیبانی شده ریلیز Kubespray باشد
- نسخه چارت‌ها به صورت جداگانه از نسخه اپلیکیشن ردیابی می‌شوند

### چارت‌های Helm
- نسخه چارت پین است، نه نسخه اپلیکیشن
- نسخه اپلیکیشن به صورت جداگانه در ماتریس نسخه ردیابی می‌شود
- مثال: چارت `cert-manager` نسخه `v1.21.2` (اپلیکیشن `v1.21.2`)، چارت Vault نسخه `0.34.1` (اپلیکیشن `2.0.4`)

### ایمیج‌های کانتینر
- در هر جایی که پلتفرم پشتیبانی کند، با digest استقرار می‌یابند
- دیجست‌های ایمیج در `offline-artifacts/artifact-matrix.md` ثبت می‌شوند
- میirrorهای ایمیج در `registry.internal:5000/...`

### کامپوننت‌های کوبرنتیز
- CNI (Cilium)، CSI (Rook-Ceph)، Ingress (NGINX Gateway Fabric)
- هرکدام با نسخه چارت و نسخه اپلیکیشن ردیابی می‌شوند
- کامپوننت‌های مدیریت‌شده توسط Kubespray و مدیریت‌شده توسط پلتفرم به وضوح متمایز شده‌اند

## نگهداری ماتریس نسخه

### مرجع
- **منبع حقیقت**: `compatibility/version-matrix.md`
- **تاریخ بررسی**: در بالای ماتریس نسخه ثبت شده (مثال: «Check date: 2026-10-17»)
- **رویه بازخوانی**: اجرای `scripts/fetch_versions.py`، `scripts/helm_chart_versions.py`، `scripts/github_latest_releases.py` در محیط متصل

### فرآیند به‌روزرسانی
1. اجرای اسکریپت‌های fetch در محیط متصل
2. Diff در برابر ماتریس نسخه فعلی
3. تأیید محدودیت‌های سازگاری
4. باز کردن MR با:
   - ماتریس نسخه به‌روزرسانی شده
   - ماتریس آرتیفکت به‌روزرسانی شده (`offline-artifacts/artifact-matrix.md`)
   - راهنمای(های) کامپوننت به‌روزرسانی شده
   - تاریخ بررسی در پیام کامیت

## سازگاری کامپوننت‌به‌کامپوننت

محدودیت‌های حیاتی که باید برقرار باشند:

| قيد | قانون | تأیید |
|---|---|---|
| Kubespray → Kubernetes | نسخه هدف K8s در بازه پشتیبانی شده ریلیز Kubespray | Kubespray release README |
| Kubespray → Ansible | ansible-core نسخه هر ریلیز | Kubespray `docs/ansible/ansible.md` |
| Kubespray → containerd | از containerd که Kubespray حمل می‌کند استفاده کنید | Kubespray release README |
| Kubespray → CNI | Cilium/Calico همانطور که ریلیز حمل می‌کند | همان |
| Rook → Ceph | `cephVersion.image` باید با ریلیز Rook پین شده همخوانی داشته باشد | یادداشت‌های انتشار Rook |
| Vault chart → Vault binary | appVersion چارت نسخه Vault binary را تعریف می‌کند | `helm show chart vault` |
| Argo CD chart → Argo CD image | appVersion چارت ایمیج را تعریف می‌کند | `helm show chart argo-cd` |
| GPU Operator → driver | `driver.version` اپراتور با toolkit هم‌خوانی دارد | یادداشت‌های انتشار GPU Operator |
| MIG → driver | H100/H200 نیاز به driver ≥ 450.80.02 روی CUDA 12 | راهنمای کاربر NVIDIA MIG |
| vLLM → driver/CUDA | vLLM روی نسخه CUDA که درایور پشتیبانی می‌کند اجرا شود | مستندات نصب vLLM برای ریلیز پین شده |

## حالت‌های چرخه حیات نسخه

| حالت | تعریف | اقدام |
|---|---|---|
| **Supported** | به طور فعال تست شده، پچ‌های امنیتی موجود | استقرار عادی |
| **Maintenance** | فقط فیکس‌های حیاتی/امنیتی | برنامه‌ریزی مهاجرت |
| **Deprecated** | برای استقرارهای جدید توصیه نمی‌شود | برنامه‌ریزی مهاجرت در ۶ ماه |
| **Retired** | پشتیبانی وجود ندارد، پچ وجود ندارد | باید بلافاصله مهاجرت کرد |
| **End-of-Life** | EOL آپستریم | باید بلافاصله مهاجرت کرد |

### ردیابی EOL
- در `compatibility/version-matrix.md` بخش «End-of-life and retirement watchlist» ردیابی می‌شود
- ماهانه در زمان بازخوانی نسخه مرور می‌شود
- مهاجرت قبل از تاریخ EOL برنامه‌ریزی شود

| Vault | 0.34.1 | 2.0.4 | Chart |

**قاعده**: نسخه چارت پین است. نسخه اپلیکیشن اطلاعی است اما برای سازگاری ردیابی می‌شود.

## دیجست‌های ایمیج و چک‌سام‌های آرتیفکت

- در `offline-artifacts/artifact-matrix.md` ثبت می‌شوند
- فرمت: `sha256:<digest>`
- در حین استیج Air-gap تأیید می‌شوند
- `skopeo inspect` برای تأیید دیجست‌ها استفاده می‌شود

## در دسترس ماندن نسخه‌های قبلی

- نسخه‌های قبلی پشتیبانی شده در ماتریس نسخه با وضعیت نگه داشته می‌شوند
- حداقل یک نسخه قبلی برای هر کامپوننت به عنوان fallback نگه داشته می‌شود
- نسخه‌های deprecated علامت‌گذاری شده اما برای ارجاع نگه داشته می‌شوند
- رویه‌های rollback به نسخه‌های قبلی ارجاع دارند

## مستندات ارتقا

ارتقای هر کامپوننت در `lifecycle/upgrades/` مستند شده:
- مسیر ارتقا و پیش‌نیازها
- رویه قدم‌به‌قدم
- رویه rollback
- تغییرات breaking و یادداشت‌های مهاجرت
- معیارهای اعتبارسنجی

## شناسایی نسخه‌های Deprecated/Unsupported

- در ماتریس نسخه به عنوان **RETIRED** یا **DEPRECATED** علامت‌گذاری می‌شوند
- تاریخ‌های EOL در «End-of-life and retirement watchlist» ردیابی می‌شوند
- مسیر مهاجرت در راهنمای کامپوننت مستند شده
- برای استقرارهای جدید در دسترس نیستند

