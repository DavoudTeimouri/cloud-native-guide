# استانداردهای مستندات

این سند قراردادهای مستندات برای راهنمای پیاده‌سازی استک کلود-بومی را تعریف می‌کند. هر راهنمای کامپوننت باید این ساختار را دنبال کند.

## ساختار سند

هر راهنمای کامپوننت باید این ساختار ۱۴ بخش را دنبال کند:

```
# <نام کامپوننت>

Status: DRAFT | REVIEWED | ACCEPTED
Owner: <تیم>
Last reviewed: YYYY-MM-DD
Applies to version: <نسخه پین شده>
Source of truth: <URL مستندات رسمی + تاریخ بررسی>

## ۱. هدف و معماری
## ۲. نسخه‌های پشتیبانی شده و سازگاری
## ۳. پیش‌نیازها
## ۴. نیازمندی‌های شبکه و فایروال
## ۵. نصب
## ۶. پیکربندی
## ۷. نصب Air-Gap
## ۸. اعتبارسنجی و بررسی سلامت
## ۹. مانیتورینگ و هشداردهی
## ۱۰. ارتقا
## ۱۱. مهاجرت
## ۱۲. بکاپ و بازیابی
## ۱۴. عیب‌یابی
## ۱۵. Rollback و محدودیت‌ها
```

## دستورالعمل‌های بخش‌ها

### ۱. هدف و معماری
- **هدف**: این کامپوننت در این پلتفرم چه مسئله‌ای را حل می‌کند
- **معماری**: چگونه arrangه شده (در صورت مفید نمودار Mermaid)
- **وابستگی‌ها**: چه چیزی نیاز دارد، و روی چه چیزی نباید وابسته باشد
- **مکان استقرار**: در چه رول/کلاستری اجرا می‌شود
- **مدل پیشنهادی تولید**: پیکربندی استفاده شده در تولید
- **جایگزین‌ها و معیار تصمیم**: چه موارد دیگری در نظر گرفته شده و چه زمانی جایگزین برنده است. ADR را لینک کنید.

### ۲. نسخه‌های پشتیبانی شده و سازگاری
| مورد | نیازمندی |
|---|---|
| OS | |
| Version | |
| CPU | |
| RAM | |
| Storage | |
| Network | |
| Dependencies | |
| Licensing | |
| Compatibility Constraints | |

جدول سازگاری با تاریخ بررسی و URL منبع. موارد تأییدنشده به عنوان **UNVERIFIED** با رویه تأیید علامت‌گذاری می‌شوند.

### ۳. پیش‌نیازها
- وابستگی‌های زیرساختی
- وابستگی‌های نرم‌افزاری
- پیش‌نیازهای پیکربندی
- اعتبارها و رازهای لازم

### ۴. نیازمندی‌های شبکه و فایروال
- پورت‌های inbound/outbound مورد نیاز
- قطعات شبکه و VLANها
- نیازمندی‌های DNS
- نیازمندی‌های Load Balancer

### ۵. نصب
- **پیش‌نیازها**
- **بستر اجرا**: دستورات روی کدام host/cluster اجرا می‌شوند
- **امتیازات**: قابلیت‌های مورد نیاز
- **دستورات به ترتیب**: شماره‌گذاری شده، قابل اجرا
- **مسیر فایل‌ها**: هر فایلی که نوشته می‌شود
- **مثال‌های پیکربندی**: YAML/values واقعی، با مثال sanitized
- **توضیح پارامترها**: وظیفه هر کلید
- **مقادیر محیطی**: کدام مقادیر در هر محیط تغییر می‌کنند

### ۶. پیکربندی
- مثال‌های فایل پیکربندی (sanitized)
- توضیح پارامترهای کلیدی
- Overrideهای محیطی
- یکپارچه‌سازی با سیستم‌های پلتفرم (Vault، مانیتورینگ و...)

### ۷. نصب Air-Gap
- منابع رسمی (URLها)
- پکیج‌ها: نام‌ها و نسخه‌ها
- Images: مسیر کامل image و tagها
- Charts: chart و نسخه
- Plugins: نام‌ها و نسخه‌ها
- وابستگی‌های واسطه: کلِ closure
- نگاشت مخزن داخلی: source -> مسیر داخلی
- تأیید یکپارچگی: دستور دقیق
- پیکربندی کلاینت مورد نیاز: فایل‌هایی که تغییر می‌کنند

### ۸. اعتبارسنجی و بررسی سلامت
- **Health Checks**: دستورات و خروجی مورد انتظار
- **خروجی‌های مورد انتظار**: مثال‌های دقیق
- **تست‌های عملکردی**
- **تست‌های شکست**: چه اتفاقی وقتی یک وابستگی down است
- **تست‌های عملکرد**: بنچمارک و اعداد مورد انتظار
- **اعتبارسنجی خودکار**: اسکریپت و محل اجرا

### ۹. مانیتورینگ و هشداردهی
- متریک‌ها و endpointهای expose شده
- هشدارهای کلیدی با لینک runbook
- ارجاع داشبورد
- تعاریف SLO/SLI

### ۱۰. ارتقا
- مسیر ارتقا و پیش‌نیازها
- رویه ارتقا قدم‌به‌قدم
- رویه rollback
- تغییرات breaking و یادداشت‌های مهاجرت

### ۱۱. مهاجرت
- سناریوهای مهاجرت
- رویه‌های مهاجرت داده
- ملاحظات سازگاری
- رویه‌های cutover

### ۱۲. بکاپ و بازیابی
- چه چیزی بکاپ می‌شود
- فرکانس و نگهداری بکاپ
- رویه بازیابی (تست شده)
- اهداف RTO/RPO

### ۱۳. عیب‌یابی
- لینک به runbook عیب‌یابی
- حالت‌های رایج شکست
- دستورات تشخیصی
- مسیرهای эскаلشن

### ۱۴. Rollback و محدودیت‌ها
- چه چیزی قابل rollback است
- چه چیزی قابل rollback نیست
- محدودیت‌های شناخته شده
- سناریوی disaster recovery و رویه

## قراردادهای نگارش

### دستورات و مثال‌ها
- **قابل کپی/پیست**: هر دستور باید مستقیماً قابل اجرا باشد
- **Placeholderهای صریح**: فرمت `<PLACEHOLDER>`، توضیح هر مقدار
- **بستر**: بستر اجرا را بیان کنید (کدام host، cluster، namespace)
- **امتیازات**: قابلیت‌های مورد نیاز را بیان کنید (sudo، cluster-admin، ...)

### فرمت‌بندی
- **bold** برای عناصر UI، **`code`** برای دستورات/مسیرها
- جداول برای داده‌های ساختاریافته
- نمودار Mermaid برای معماری
- لیست‌های شماره‌دار برای رویه‌های مرتب

### Placeholderها
فرمت `<UPPERCASE_PLACEHOLDER>` با توضیح واضح:
```yaml
server: "<VAULT_SERVER_URL>"  # e.g., https://vault.internal:8200
```

### زبان
- محتوای فنی انگلیسی و فارسی معادل باید باشد
- اسکریپت‌ها و پیکربندی‌ها مشترک — دو پیاده‌سازی مستقل نکنید
- Cross-link بین نسخه‌های زبانی
- ترجمه‌های گمشده قابل تشخیص از طریق `tests/test_repo_tools.py`

## مقادیر Status

| Status | معنی |
|---|---|
| **DRAFT** | پیش‌نویس اولیه، بررسی نشده |
| **REVIEWED** | توسط owner بررسی شده، ممکن است کامنت باز داشته باشد |
| **ACCEPTED** | برای استفاده در تولید تأیید شده |
