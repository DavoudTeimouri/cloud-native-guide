# Architecture decision template

## Purpose
Record an Architecture Decision Record (ADR) for a significant architectural decision.

## Sections
1. Title and status (Proposed / Accepted / Deprecated / Superseded)
2. Context and problem statement
3. Decision
4. Alternatives considered
5. Technical reasoning and trade-offs
6. Operational complexity
7. Security implications
8. Migration considerations
9. Related ADRs

## Rules
- Never silently replace an existing architectural decision.
- Record justified architectural changes in new ADRs.
- Preserve ADR history and numbering (ADR-0001..ADR-0031).

## Placeholders
- `<TITLE>`, `<STATUS>`, `<CONTEXT>`, `<DECISION>`, `<ALTERNATIVES>`
