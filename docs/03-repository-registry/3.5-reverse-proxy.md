# Reverse Proxy Architecture

## Purpose and scope
Configure reverse proxies to preserve original repository/registry addresses wherever technically possible: DNS/hostname preservation, TLS termination/passthrough, path routing, header forwarding, Docker/OCI/Helm/package-manager compatibility.

## Capabilities
- Docker Registry compatibility: yes (Harbor behind proxy)
- OCI compatibility: yes
- Helm repositories: yes
- Package manager compatibility: yes (with path routing)

## Limitations
- Some protocols cannot transparently operate behind a reverse proxy; document these with technical explanations and alternatives.
- Never claim every repository/protocol works transparently behind a reverse proxy.
