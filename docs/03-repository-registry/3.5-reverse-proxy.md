# Reverse Proxy Architecture

## Purpose and scope

Configure reverse proxies to preserve original repository/registry addresses wherever technically possible: DNS/hostname preservation, TLS termination/passthrough, path routing, header forwarding, Docker/OCI/Helm/package-manager compatibility. Includes real reverse proxy configurations for HAProxy and NGINX, per-registry reverse proxy mappings, and guidance on which protocols cannot transparently operate behind a reverse proxy.

## Supported vs unsupported proxy configurations

| Platform | Docker/OCI registry | Helm charts | RPM/DEB (YUM/APT) | Maven/PyPI/npm | Git (HTTP/SSH) | Notes |
| --- | --- | --- | --- | --- | --- | --- |
| Harbor | Yes | Yes | No | No | No | Registry v2 API works through reverse proxy |
| Nexus | Yes | Yes | Yes | Yes | No | Group repos simplify client config |
| GitLab Container Registry | Yes | Yes | No | No | No | Container registry subdomain preferred |
| Artifactory | Yes | Yes | Yes | Yes | Yes | Universal reverse proxy support |

**Protocols that cannot transparently operate behind a reverse proxy:**

| Protocol | Issue | Solution |
| --- | --- | --- |
| Docker Registry v1 | No manifest schema v2 support | Use Docker Registry v2 (Harbor/Nexus) |
| Git SSH | SSH cannot terminate at HTTP reverse proxy | Use separate SSH port or GitLab SSH endpoint directly |
| Docker chunked upload | Some proxies buffer large uploads | Increase proxy buffer size or bypass for uploads |

## HAProxy reverse proxy configuration

### Option A: Docker Compose (container-based)

```bash
# 1. Create directory
mkdir -p /opt/haproxy/{certs,config}

# 2. Copy TLS certificates (from internal CA)
cp /etc/pki/ca-trust/source/anchors/internal-ca.crt /opt/haproxy/certs/
cp /etc/registry/certs/harbor.internal.crt /opt/haproxy/certs/harbor.internal.crt
cp /etc/registry/certs/harbor.internal.key /opt/haproxy/certs/harbor.internal.key
cp /etc/registry/certs/nexus.internal.crt /opt/haproxy/certs/nexus.internal.crt
cp /etc/registry/certs/nexus.internal.key /opt/haproxy/certs/nexus.internal.key
cp /etc/gitlab/ssl/gitlab.internal.crt /opt/haproxy/certs/gitlab.internal.crt
cp /etc/gitlab/ssl/gitlab.internal.key /opt/haproxy/certs/gitlab.internal.key

# 3. Combine cert + key into single .pem files for HAProxy
cat /opt/haproxy/certs/harbor.internal.crt /opt/haproxy/certs/harbor.internal.key > /opt/haproxy/certs/harbor.internal.pem
cat /opt/haproxy/certs/nexus.internal.crt /opt/haproxy/certs/nexus.internal.key > /opt/haproxy/certs/nexus.internal.pem
cat /opt/haproxy/certs/gitlab.internal.crt /opt/haproxy/certs/gitlab.internal.key > /opt/haproxy/certs/gitlab.internal.pem

# 4. Create docker-compose.yml
cat > /opt/haproxy/docker-compose.yml <<'EOF'
version: '3.8'

services:
  haproxy:
    image: haproxy:2.8
    container_name: haproxy
    restart: unless-stopped
    ports:

      - "80:80"
      - "443:443"
      - "8443:8443"
      - "4443:4443"
    volumes:

      - ./haproxy.cfg:/usr/local/etc/haproxy/haproxy.cfg:ro
      - ./certs:/etc/haproxy/certs:ro
    networks:

      - lb-net

networks:
  lb-net:
    driver: bridge
EOF

# 5. Create haproxy.cfg
cat > /opt/haproxy/haproxy.cfg <<'EOF'
global
    log /dev/log local0
    maxconn 4096
    user haproxy
    group haproxy
    daemon

defaults
    log global
    mode tcp
    option tcplog
    option dontlognull
    retries 3
    timeout connect 5000
    timeout client 50000
    timeout server 50000

frontend harbor-frontend
    bind *:443 ssl crt /etc/haproxy/certs/harbor.internal.pem
    mode tcp
    option tcplog
    use_backend harbor-backend

backend harbor-backend
    mode tcp
    balance roundrobin
    option tcplog
    timeout server 600000
    server harbor1 10.10.0.50:443 check fall 3 rise 2

frontend nexus-frontend
    bind *:8443 ssl crt /etc/haproxy/certs/nexus.internal.pem
    mode tcp
    option tcplog
    use_backend nexus-backend

backend nexus-backend
    mode tcp
    balance roundrobin
    option tcplog
    server nexus1 10.10.0.51:8081 check fall 3 rise 2

frontend gitlab-registry-frontend
    bind *:4443 ssl crt /etc/haproxy/certs/gitlab.internal.pem
    mode tcp
    option tcplog
    use_backend gitlab-registry-backend

backend gitlab-registry-backend
    mode tcp
    balance roundrobin
    option tcplog
    server gitlab-registry1 10.10.0.52:5000 check fall 3 rise 2

frontend http-redirect
    bind *:80
    mode http
    reqadd X-Forwarded-Proto:\ http
    default_backend http-https-redirect

backend http-https-redirect
    mode http
    redirect scheme https code 301 if !{ ssl_fc }
EOF

# 6. Start
docker-compose -f /opt/haproxy/docker-compose.yml up -d

# 7. Verify
docker-compose -f /opt/haproxy/docker-compose.yml ps
curl -sk -I https://harbor.internal:443/
```

**Customization hints:**

- Change `haproxy:2.8` to your preferred HAProxy version
- Edit backend server IPs (`10.10.0.50`, `10.10.0.51`, `10.10.0.52`) to match your registry nodes
- Replace certificate paths with your internal CA cert locations
- Increase `timeout server` for large image uploads

### Option B: Native installation (RHEL-family)

```bash
# 1. Install HAProxy
dnf install -y haproxy

# 2. Create configuration directory
mkdir -p /etc/haproxy/certs

# 3. Copy TLS certificates
cp /etc/registry/certs/harbor.internal.crt /etc/haproxy/certs/
cp /etc/registry/certs/harbor.internal.key /etc/haproxy/certs/

# 4. Combine cert + key into single .pem
cat /etc/haproxy/certs/harbor.internal.crt /etc/haproxy/certs/harbor.internal.key > /etc/haproxy/certs/harbor.internal.pem

# 5. Create /etc/haproxy/haproxy.cfg (see Docker Compose section above for full config)
# Copy the haproxy.cfg from the Docker Compose section into /etc/haproxy/haproxy.cfg

# 6. Validate config
haproxy -c -f /etc/haproxy/haproxy.cfg

# 7. Enable and start
systemctl enable --now haproxy

# 8. Verify
systemctl status haproxy
curl -sk -I https://harbor.internal:443/
```

**Customization hints:**

- Edit `/etc/haproxy/haproxy.cfg` backends for your registry IPs
- Change `timeout server` for large image uploads (default 50s, increase to 600s)
- Set certificate paths to match your cert storage location

## NGINX reverse proxy configuration

### Option A: Docker Compose (container-based)

```bash
# 1. Create directory
mkdir -p /opt/nginx/{certs,config}

# 2. Copy TLS certificates
cp /etc/registry/certs/harbor.internal.crt /opt/nginx/certs/
cp /etc/registry/certs/harbor.internal.key /opt/nginx/certs/

# 3. Create docker-compose.yml
cat > /opt/nginx/docker-compose.yml <<'EOF'
version: '3.8'

services:
  nginx:
    image: nginx:1.25
    container_name: nginx
    restart: unless-stopped
    ports:

      - "80:80"
      - "443:443"
      - "8443:8443"
    volumes:

      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certs:/etc/nginx/certs:ro
    networks:

      - lb-net

networks:
  lb-net:
    driver: bridge
EOF

# 4. Create nginx.conf
cat > /opt/nginx/nginx.conf <<'EOF'
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

include /usr/share/nginx/modules/*.conf;

events {
    worker_connections 4096;
    use epoll;
    multi_accept on;
}

http {
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    types_hash_max_size 2048;

    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    # Harbor - Docker/OCI registry
    upstream harbor_backend {
        server 10.10.0.50:443;
    }

    # Nexus - package repository
    upstream nexus_backend {
        server 10.10.0.51:8081;
    }

    # GitLab Container Registry
    upstream gitlab_registry_backend {
        server 10.10.0.52:5000;
    }

    # Harbor server block (Docker/OCI + Helm)
    server {
        listen 443 ssl;
        server_name harbor.internal;

        ssl_certificate /etc/nginx/certs/harbor.internal.crt;
        ssl_certificate_key /etc/nginx/certs/harbor.internal.key;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers HIGH:!aNULL:!MD5;

        # Docker Registry v2 requires chunked transfer
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Docker-Distribution-Api-Version "registry/2.0";

        # No buffering for image uploads
        proxy_request_buffering off;
        proxy_buffering off;

        location / {
            proxy_pass https://harbor_backend;
        }
    }

    # Nexus server block (RPM, DEB, Maven, PyPI, npm)
    server {
        listen 8443 ssl;
        server_name nexus.internal;

        ssl_certificate /etc/nginx/certs/nexus.internal.crt;
        ssl_certificate_key /etc/nginx/certs/nexus.internal.key;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers HIGH:!aNULL:!MD5;

        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        location / {
            proxy_pass http://nexus_backend;
        }
    }

    # GitLab Container Registry
    server {
        listen 4443 ssl;
        server_name registry.gitlab.internal;

        ssl_certificate /etc/nginx/certs/gitlab.internal.crt;
        ssl_certificate_key /etc/nginx/certs/gitlab.internal.key;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers HIGH:!aNULL:!MD5;

        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Docker-Distribution-Api-Version "registry/2.0";
        proxy_request_buffering off;
        proxy_buffering off;

        location / {
            proxy_pass http://gitlab_registry_backend;
        }
    }

    # HTTP to HTTPS redirect
    server {
        listen 80;
        server_name _;
        return 301 https://$host$request_uri;
    }
EOF

# 5. Start
docker-compose -f /opt/nginx/docker-compose.yml up -d

# 6. Verify
docker-compose -f /opt/nginx/docker-compose.yml ps
curl -sk -I https://harbor.internal:443/
```

**Customization hints:**

- Change `nginx:1.25` to your preferred NGINX version
- Edit `upstream` blocks to point at your backend IPs
- Replace certificate paths with your internal cert locations
- Adjust `proxy_buffering`/`proxy_request_buffering` for large image uploads

### Harbor behind reverse proxy

Harbor works transparently behind a reverse proxy for Docker/OCI and Helm:

```bash

# Client configuration (Docker/containerd)

# /etc/containerd/config.toml

[plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
  endpoint = ["https://harbor.internal:443"]

# Client Docker config

cat ~/.docker/config.json
{
  "auths": {
    "harbor.internal:443": {
      "auth": "base64encodedusername:password"
    }
  }
}
```

### Nexus behind reverse proxy

Nexus works transparently behind a reverse proxy for all package types:

```bash

# YUM/DNF - use Nexus group repo URL

cat /etc/yum.repos.d/internal.repo
[internal-nexus]
name=Internal Nexus Repository
baseurl=https://nexus.internal:8443/repository/maven-public/
enabled=1
gpgcheck=0

# APT

cat /etc/apt/sources.list.d/internal.list
deb https://nexus.internal:8443/repository/debian-public/ bookworm main contrib non-free

# npm

npm config set registry https://nexus.internal:8443/repository/npm-public/

# pip

pip config set global.index-url https://nexus.internal:8443/repository/pypi-public/simple
```

### GitLab Container Registry behind reverse proxy

GitLab Container Registry works behind a reverse proxy but requires the `Docker-Distribution-Api-Version` header:

```bash

# Docker client

docker login registry.gitlab.internal:4443 -u gitlab-ci-token -p <job_token>

# containerd mirror

[plugins."io.containerd.grpc.v1.cri".registry.mirrors."registry.gitlab.internal:4443"]
  endpoint = ["https://registry.gitlab.internal:4443"]
```

### Protocols that do NOT work behind reverse proxy

| Protocol | Issue | Solution |
| --- | --- | --- |
| Git SSH (port 22) | SSH cannot terminate at HTTP reverse proxy | Use separate SSH port or direct GitLab SSH endpoint |
| Docker Registry v1 | No manifest schema v2 support | Use Harbor/Nexus with Registry v2 |
| Raw TCP/UDP protocols | Reverse proxies are HTTP/TCP only | Use direct connection or load balancer (Layer 4) |

**Solution:** For protocols that cannot use reverse proxy, configure clients to connect directly to the backend service IP, or use a Layer 4 load balancer (HAProxy in TCP mode, Keepalived + HAProxy) instead of HTTP reverse proxy.
