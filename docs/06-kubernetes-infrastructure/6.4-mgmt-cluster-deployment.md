# Management Cluster Deployment

## Purpose and scope
Deploy the management cluster: AD-integrated, non-AD, local authentication. Prerequisites, inventory, configuration, deployment, validation, post-deployment preparation.

## Prerequisites
- 3+ control plane nodes (HA)
- 1+ worker nodes for platform tooling
- Load balancer for API server (6443)
- Internal repository/registry reachable
- Operational server with Ansible/Kubespray

## Inventory design
Groups: `kube_control_plane`, `etcd`, `kube_node`, `k8s_cluster`, `calico_rr`.
Separate inventory per environment (mgmt, app1, app2).

## Deployment steps
1. Prepare OS on all nodes (see 02-components)
2. Write inventory and group_vars
3. Run Kubespray playbook: `ansible-playbook -i inventory/mycluster/hosts.yaml cluster.yml`
4. Validate: `kubectl get nodes`, `kubectl get --raw=/readyz`
5. Deploy platform tooling (monitoring, logging, ingress)

## Authentication modes
- AD-integrated: via Rancher/dex OIDC after cluster up
- Non-AD: local Kubernetes RBAC + static admin
- Local authentication: bootstrap admin kubeconfig only

## Validation
- All control plane nodes Ready, etcd quorum healthy
- API server readyz ok
- CoreDNS running
- Ingress controller available
