# 6.16 Security and Identity

## Purpose and scope
AD integration, LDAP, OIDC, RBAC, service accounts, secrets management, certificates, network segmentation, API security, audit logging.

## Authentication
- Humans authenticate through Keycloak (OIDC/LDAP federation). No host-level AD join (ADR-0015).
- Kubernetes authenticates users via Keycloak OIDC; service accounts are per-application, never shared.
- Local authentication disabled for daily use; break-glass local admin retained.

## RBAC
- Least privilege; namespace-scoped for application teams.
- cluster-admin held by two named operators.
- Service accounts per application, never shared.
- pods/exec and pods/portforward restricted (equivalent to shell on node).
- Quarterly review of cluster-role bindings and Argo CD project permissions.

## Secrets management
- Vault only; never in Git, images, logs, or values files.
- Kubernetes Secrets hold synchronized copy where delivery requires it (separate access boundary, audited).
- Every secret has owner, rotation interval, documented revocation path.
- Break-glass credentials held offline and tested quarterly.

## Certificates
- One internal CA rooted in Vault PKI; root key offline.
- cert-manager issues and renews every in-cluster certificate.
- Leaf lifetime 90 days; renewal at 30 days remaining.
- Expiry alerting at 14 days (warning) and 7 days (page).
- Root CA rotation: multi-step runbook, not one-line operation.

## Network segmentation
- Segments: mgmt, control-plane, pod, service, storage, GPU, DMZ, nodeport.
- Default deny inbound; explicit allow rules generated from network matrix.
- One firewall implementation per host; never two.

## API security
- kube-apiserver fronted by control-plane VIP.
- Authentication via OIDC; authorization via RBAC.
- Audit logging: level Metadata; RequestResponse on secrets requires documented decision.
