# Additional Application Clusters

## Purpose and scope
Complete lifecycle of adding new application clusters: capacity planning, network planning, IP allocation, load balancers, deployment, integration, registration, monitoring, security policies.

## Steps
1. Capacity planning: node count, sizing profile (see 6.5)
2. Network planning: pod CIDR, service CIDR, IP pools, VLAN
3. IP allocation: node IPs, LB VIPs, control plane endpoints
4. Provision load balancers (see 05-load-balancers)
5. Deploy cluster (see 6.5 Application Cluster Deployment)
6. Integrate: CNI, CSI, ingress, monitoring
7. Register to Rancher/Argo CD
8. Apply security policies (network policies, RBAC, Pod Security Standards)
9. Onboard workloads via GitOps (Argo CD ApplicationSet)

## Validation
- New cluster appears in management platform
- Workloads deploy via GitOps
- Monitoring targets scrape new cluster
- Alerts route correctly
