# 6.7 Kubernetes Management Platform

## Purpose and scope
Rancher deployment on the management cluster: installation, HA, TLS, DNS, load balancer integration, AD/LDAP integration, local authentication, RBAC, cluster registration, multi-cluster management, backup and restore.

## Install
Add the Rancher Helm chart repository and install on the management cluster:

```
helm repo add rancher-stable https://releases.rancher.com/server-charts/stable
helm repo update
helm install rancher rancher-stable/rancher \
  --namespace cattle-system \
  --create-namespace \
  --set hostname=rancher.management.internal \
  --set replicas=3 \
  --set ingress.tls.source=rancher
```

In production, Rancher is installed via Argo CD Application (GitOps), not via `helm install` on the command line. The helm command above is for reference/initial bootstrap only.

## Configure
- TLS: certificate from internal CA or cert-manager (Vault PKI or bootstrap issuer).
- Authentication: Keycloak OIDC. Local authentication disabled for daily use; break-glass local admin retained.
- RBAC: cluster-admin held by two named operators. Application teams get namespace-scoped RBAC via projects.
- Projects and namespaces: organize by team and environment (dev/staging/prod).

## Security
- No application workloads scheduled on management workers.
- Rancher never holds secret values; secrets live in Vault.
- All human access via Keycloak OIDC with MFA.
- Audit logging enabled; every Rancher API call logged.

## Backup and restore
- Rancher state (cluster registrations, RBAC, projects) backed up via etcd snapshot of the management cluster.
- Restore: redeploy management cluster, restore Rancher backup, re-register application clusters.
