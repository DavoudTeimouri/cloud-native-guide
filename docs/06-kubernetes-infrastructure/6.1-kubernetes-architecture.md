# Kubernetes Architecture

## Purpose and scope

Kubernetes control plane, worker nodes, etcd, networking, storage, API access, cluster lifecycle, multi-cluster architecture, management vs application clusters.

## Architecture overview

A production cloud-native stack runs two kinds of clusters:

- **Management cluster** — runs Rancher, Argo CD, monitoring, logging, repository/registry, load balancers, and operational tooling.
- **Application clusters** — run tenant workloads; registered to management cluster via Rancher/Argo CD.

## Components

- Control plane: API server, etcd, scheduler, controller-manager, cloud-controller-manager.
- Worker nodes: kubelet, kube-proxy, container runtime, CNI plugin.
- etcd: clustered, quorum-based, backed up regularly.
- CNI: pod networking, network policies, IPAM.
- CSI: persistent storage provisioning.

## Management vs application clusters

| Aspect | Management cluster | Application cluster |
| --- | --- | --- |
| Purpose | Platform operations, GitOps, monitoring | Tenant workloads |
| HA | 3+ control plane nodes | 3+ control plane nodes |
| Nodes | Operational tooling only | Workloads only |
| Access | Restricted to infra team | Namespaces per team/app |

## Automation: Kubespray deployment playbook

Deploy Kubernetes clusters via Ansible/Kubespray:

```bash
# Dry-run
ansible-playbook -i automation/ansible/inventories/staging/hosts.ini \
  automation/ansible/playbooks/kubernetes.yml --check --diff

# Apply to production
ansible-playbook -i automation/ansible/inventories/production/hosts.ini \
  automation/ansible/playbooks/kubernetes.yml

# Limit to management cluster
ansible-playbook -i automation/ansible/inventories/production/hosts.ini \
  automation/ansible/playbooks/kubernetes.yml --limit mgmt-cluster

# Limit to application cluster
ansible-playbook -i automation/ansible/inventories/production/hosts.ini \
  automation/ansible/playbooks/kubernetes.yml --limit app-cluster
```

**Customization variables** (`automation/ansible/group_vars/all/kubernetes.yml`):

| Variable | Default | Customize when |
| --- | --- | --- |
| `kube_version` | `1.28.x` | Pin to your Kubernetes version |
| `kube_network_plugin` | `calico` | Use `cilium` for advanced networking |
| `etcd_deployment_type` | `kubespray` | Use `stacked` for smaller clusters |
| `max_pods` | `110` | Adjust for node sizing |
| `containerd_registry_mirrors` | `["https://harbor.internal:443"]` | Your Harbor address differs |

**Cluster types** — Management cluster runs Rancher, Argo CD, monitoring; Application clusters run tenant workloads (see section 6.1).
