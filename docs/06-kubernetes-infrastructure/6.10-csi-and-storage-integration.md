# 6.10 CSI and Storage Integration

## Purpose and scope
CSI architecture, StorageClasses, PersistentVolumes, PVCs, snapshots, expansion, volume attachment, access modes, migration between storage backends.

## CSI architecture
- CSI driver enables K8s to expose arbitrary storage systems to workloads.
- Ceph CSI driver for RBD and CephFS.
- Sidecar containers: external-provisioner, external-attacher, external-resizer, external-snapshotter, node-driver-registrar.

## StorageClasses
- StorageClass per workload (replication, erasure coding, performance tier).
- `storageclass.storage.k8s.io/is-default-class` for default.
- `reclaimPolicy`: Delete or Retain.
- `volumeBindingMode`: Immediate or WaitForFirstConsumer (recommended).

## PersistentVolumes and PVCs
- PV: cluster resource, provisioned statically or dynamically.
- PVC: user request for storage, bound to PV.
- Access modes: ReadWriteOnce, ReadOnlyMany, ReadWriteMany.

## Snapshots and expansion
- VolumeSnapshots for point-in-time copies.
- Expansion: expand PVC online (if storage class supports `allowVolumeExpansion`).
- Volume attachment: node-specific, one PVC one node at a time (RWO).

## Migration between storage backends
- Add new StorageClass, migrate PVCs, update applications, delete old.
- Verify data integrity after migration.
