# Validation and Acceptance Testing

## Purpose and scope
Define practical tests for cluster HA, node failure, control-plane failure, network connectivity, storage availability, scheduling, pod resilience, DNS, ingress, monitoring, backup and restore.

## Acceptance tests
- Cluster HA: kubectl get nodes all Ready; kubectl get --raw='/readyz?verbose' all ok.
- Node failure: drain node, verify pods reschedule; verify remaining nodes Ready.
- Control-plane failure: reboot one control-plane node; verify etcd quorum preserved (3 members).
- Network connectivity: curl from pod to service; DNS resolution from test pod.
- Storage availability: test PVC binds and pod writes; StorageClass created.
- Scheduling: pod with node selector/toleration lands on correct node.
- Pod resilience: delete pod; verify restarted and Running.
- DNS: kubectl run test-dns; dig kubernetes.default.svc.cluster.local.
- Ingress: curl -vk https://<ingress-vip>/healthz returns 200 with valid cert chain.
- Monitoring: Prometheus targets scrape; Grafana dashboards load.
- Backup and restore: Velero backup created and restored in test namespace; etcd snapshot restore and unseal.

## Validation gates
- No phase starts until previous phase acceptance passes.
- Destructive actions require explicit confirmation.
- Every backup has recorded RPO and measured RTO.
- A backup that has never been restored is a hypothesis.
