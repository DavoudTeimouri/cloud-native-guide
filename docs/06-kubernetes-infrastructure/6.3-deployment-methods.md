# 6.3 Deployment Methods

## Purpose and scope
Evaluate deployment approaches and prefer Kubespray where appropriate. Document Kubespray architecture, Ansible requirements, inventory design, offline deployment, OS compatibility, version selection.

## Deployment methods
| Method | When to use | Notes |
|---|---|---|
| Kubespray | Production, on-prem, air-gapped | Preferred; Ansible-driven, HA, repeatable |
| Rancher | Multi-cluster management | Install on top of Kubespray clusters |
| Kind/minikube | Lab, CI, testing | Not production |

## Kubespray requirements
- Ansible control node (operational server)
- Python 3, jinja2, netaddr on control node
- Target OS: supported Linux distros (see 02-components)
- SSH access with sudo
- Inventory file (grouped by role: kube_control_plane, kube_node, etcd, k8s_cluster, calico_rr)

## Offline deployment
Stage container images, binaries, and Python packages on connected host; sync to internal registry; point Kubespray to internal registries.

## Version selection
Pin Kubernetes version in inventory; match Kubespray release; check version compatibility matrix.
