# GitLab

## Purpose and scope

GitLab infrastructure requirements, OS preparation, storage, networking, security, backup, dependencies. CI/CD for building, validating, scanning, and deploying Cloud-Native components.

## Requirements

- OS: Oracle Linux 9 or Ubuntu 24.04
- Disk: large disk for repositories, LFS, container registry data
- Network: internal, reachable by Argo CD and CI runners
- PostgreSQL, Redis, object storage
- Secrets file (required to restore)

## Security

- TLS via internal CA/cert-manager
- Secret file backed up separately
- Access via Keycloak OIDC or local (break-glass)

## CI/CD

- GitLab CI builds container images and Helm charts
- Scan: Trivy, Gitleaks, Checkov
- Deploy: Argo CD declares K8s state (GitOps)
- Runners: GitLab runners on internal infrastructure

## Backup

- gitlab-backup create; copy tar to object storage
- Repositories, LFS, registry data, config, encryption keys/secrets file

## Automation: GitLab playbook

Deploy GitLab via Ansible:

```bash
# Dry-run
ansible-playbook -i automation/ansible/inventories/staging/hosts.ini \
  automation/ansible/playbooks/gitlab.yml --check --diff

# Apply
ansible-playbook -i automation/ansible/inventories/production/hosts.ini \
  automation/ansible/playbooks/gitlab.yml

# Limit to GitLab node
ansible-playbook -i automation/ansible/inventories/production/hosts.ini \
  automation/ansible/playbooks/gitlab.yml --limit gitlab-nodes
```

**Customization variables** (`automation/ansible/group_vars/all/gitlab.yml`):

| Variable | Default | Customize when |
| --- | --- | --- |
| `gitlab_version` | `17.0.0` | Pin to your GitLab version |
| `gitlab_external_url` | `https://gitlab.internal` | Your GitLab address differs |
| `gitlab_root_password` | Vault lookup | Never set in plaintext |
| `gitlab_storage_size` | `1Ti` | Increase for large repos/LFS |
| `gitlab_smtp_host` | `smtp.internal` | Your SMTP relay differs |

**Backup** (section 3.7): `gitlab-rake gitlab:backup:restore BACKUP=<timestamp>` — run via Ansible or manually on the GitLab node.
