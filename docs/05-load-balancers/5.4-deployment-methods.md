# Deployment Methods

## Purpose and scope

Native deployment and container-based deployment for load balancers (HAProxy, NGINX, Keepalived). Docker Compose preferred for container-based examples; native RPM/DEB packages for bare-metal installs. Both methods include full customization hints.

## Method 1: Docker Compose (container-based)

### HAProxy via Docker Compose

```bash
# 1. Create directory
mkdir -p /opt/haproxy/{certs,config}

# 2. Copy TLS certificates (from internal CA)
cp /etc/pki/ca-trust/source/anchors/internal-ca.crt /opt/haproxy/certs/
cp /etc/registry/certs/harbor.internal.crt /opt/haproxy/certs/harbor.internal.crt
cp /etc/registry/certs/harbor.internal.key /opt/haproxy/certs/harbor.internal.key

# 3. Combine cert + key into single .pem for HAProxy
cat /opt/haproxy/certs/harbor.internal.crt /opt/haproxy/certs/harbor.internal.key > /opt/haproxy/certs/harbor.internal.pem

# 4. Create docker-compose.yml
cat > /opt/haproxy/docker-compose.yml <<'EOF'
version: '3.8'

services:
  haproxy:
    image: haproxy:2.8
    container_name: haproxy
    restart: unless-stopped
    ports:

      - "80:80"
      - "443:443"
      - "8443:8443"
      - "4443:4443"
    volumes:

      - ./haproxy.cfg:/usr/local/etc/haproxy/haproxy.cfg:ro
      - ./certs:/etc/haproxy/certs:ro
    networks:

      - lb-net

networks:
  lb-net:
    driver: bridge
EOF

# 5. Create haproxy.cfg (see 5.5-configuration-operations.md for full example)
# Copy the HAProxy config from section 5.5 into ./haproxy.cfg

# 6. Start
docker-compose -f /opt/haproxy/docker-compose.yml up -d

# 7. Verify
docker-compose -f /opt/haproxy/docker-compose.yml ps
curl -sk -I https://harbor.internal:443/
```

**Customization hints:**

- Change `haproxy:2.8` to your preferred HAProxy version
- Edit `haproxy.cfg` backends to point at your actual registry/LB node IPs
- Replace certificate paths with your internal CA cert locations
- Adjust ports if your environment uses non-standard HTTPS ports

### NGINX via Docker Compose

```bash
# 1. Create directory
mkdir -p /opt/nginx/{certs,config}

# 2. Copy TLS certificates
cp /etc/registry/certs/harbor.internal.crt /opt/nginx/certs/
cp /etc/registry/certs/harbor.internal.key /opt/nginx/certs/

# 3. Create docker-compose.yml
cat > /opt/nginx/docker-compose.yml <<'EOF'
version: '3.8'

services:
  nginx:
    image: nginx:1.25
    container_name: nginx
    restart: unless-stopped
    ports:

      - "80:80"
      - "443:443"
      - "8443:8443"
    volumes:

      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certs:/etc/nginx/certs:ro
    networks:

      - lb-net

networks:
  lb-net:
    driver: bridge
EOF

# 4. Create nginx.conf (see 5.5-configuration-operations.md for full example)
# Copy the NGINX config from section 5.5 into ./nginx.conf

# 5. Start
docker-compose -f /opt/nginx/docker-compose.yml up -d
```

**Customization hints:**

- Change `nginx:1.25` to your preferred NGINX version
- Edit `nginx.conf` upstream blocks to point at your backend IPs
- Replace certificate paths with your internal cert locations
- Adjust `proxy_buffering` and `proxy_request_buffering` for large image uploads

### Keepalived VIP via Docker (optional, for HA)

```bash
# Keepalived runs with NET_ADMIN capability for VIP management
docker run -d \
  --name keepalived \
  --cap-add NET_ADMIN \
  --network host \
  -v ./keepalived.conf:/etc/keepalived/keepalived.conf:ro \
  osixia/keepalived:2.0.1
```

**Customization hints:**

- Set `virtual_router_id` uniquely per cluster
- Set `virtual_ipaddress` to your LB VIP
- Set `interface` to your actual network interface name

## Method 2: Native installation (OS packages, systemd)

### HAProxy native install (RHEL-family)

```bash
# 1. Install HAProxy
dnf install -y haproxy

# 2. Create configuration directory
mkdir -p /etc/haproxy/certs

# 3. Copy TLS certificates
cp /etc/registry/certs/harbor.internal.crt /etc/haproxy/certs/
cp /etc/registry/certs/harbor.internal.key /etc/haproxy/certs/

# 4. Combine cert + key into single .pem
cat /etc/haproxy/certs/harbor.internal.crt /etc/haproxy/certs/harbor.internal.key > /etc/haproxy/certs/harbor.internal.pem

# 5. Create /etc/haproxy/haproxy.cfg (see 5.5-configuration-operations.md)
# Copy the HAProxy config from section 5.5

# 6. Validate config
haproxy -c -f /etc/haproxy/haproxy.cfg

# 7. Enable and start
systemctl enable --now haproxy

# 8. Verify
systemctl status haproxy
curl -sk -I https://harbor.internal:443/
```

**Customization hints:**

- Edit `/etc/haproxy/haproxy.cfg` backends for your registry IPs
- Change `timeout server` for large image uploads (default 50s, increase to 600s)
- Set `ssl_certificate_path` to match your cert storage location

### HAProxy native install (Ubuntu/Debian)

```bash
# 1. Install HAProxy
apt-get install -y haproxy

# 2. Enable service (Debian requires manual enable)
systemctl enable haproxy
systemctl start haproxy

# 3. Same config as RHEL-family at /etc/haproxy/haproxy.cfg
```

### Keepalived native install (VIP management)

```bash
# RHEL-family
dnf install -y keepalived

# Ubuntu/Debian
apt-get install -y keepalived

# Create /etc/keepalived/keepalived.conf
cat > /etc/keepalived/keepalived.conf <<'EOF'
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1
    virtual_ipaddress {
        10.10.0.10  # LB VIP - change to your VIP
    }
    track_script {
        chk_haproxy
    }
}

vrrp_script chk_haproxy {
    script "curl -sk https://127.0.0.1:443/ || exit 1"
    interval 2
    weight 2
    fall 2
    rise 2
    timeout 5
}
EOF

# Enable and start
systemctl enable --now keepalived
```

**Customization hints:**

- Change `interface eth0` to your actual network interface
- Change `virtual_router_id` to a unique number per cluster
- Change `virtual_ipaddress` to your LB VIP
- Change `priority` (100 = master, lower = backup)

## Method comparison

 Method | Best for | Pros | Cons |
 --- | --- | --- | --- |
 Docker Compose | Containerized environments, easy migration | Portable, isolated, version-pinned | Extra container overhead, Docker daemon required |
 Native RPM/DEB | Bare-metal, performance-critical | Direct hardware access, no container overhead | OS-specific packages, manual systemd management |
 Keepalived | HA VIP management | Automatic failover, VRRP standard | Requires NET_ADMIN, interface-specific |

**Selection guidance:**

- Use Docker Compose if you already run containers and want portability
- Use Native RPM/DEB for bare-metal performance or when Docker isn't available
- Use Keepalived for VIP failover between LB nodes (can combine with either method above)
