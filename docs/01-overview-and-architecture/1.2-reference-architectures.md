# 1.2 Reference Architectures

## Purpose and scope
Document complete reference architectures: Cloud-Native infrastructure, management and application cluster separation, shared services, storage, network and security, HA, DR, connected/disconnected/isolated deployment architectures, small/medium/large scenarios, physical and virtual architectures.

## Reference architecture layers
| Layer | Components | Failure impact |
|---|---|---|
| Physical | Servers, PDUs, switches | Node loss; storage tolerates |
| Offline distribution | Harbor, Nexus, RPM/DEB mirrors, GitLab | New deployments blocked; running workloads unaffected |
| Automation | Automation Management Server, Ansible, AWX, GitLab Runner | Changes blocked; workloads unaffected |
| Identity & secrets | Keycloak (broker), OIDC/LDAP federation, Vault, internal CA | Login blocked; workloads keep running |
| Storage | Ceph MON/MGR/OSD/MDS/RGW, Rook operator | PVC IO blocks; pod restart loop |
| Kubernetes | Control plane, etcd, CNI, CSI | Scheduling/API blocked; running pods keep IP |
| GitOps | Argo CD, GitLab | New/changed deploys blocked; no auto-revert |
| Management | Rancher, Prometheus, Grafana, Loki | Visibility lost; no data plane impact |

## Control / data plane split
- Management cluster — Rancher, Argo CD, Keycloak, Prometheus/Grafana, GitLab runner. Dedicated infrastructure worker pool, no application workloads.
- Application clusters — general workers, GPU workers, storage-facing workers. No Rancher, no Vault server, no GitLab.

## Deployment sizes
| Size | Control plane | Workers | etcd | Use case |
|---|---|---|---|---|
| Small | 3 | 3+ | stacked | Lab, staging, small site |
| Medium | 3 | 5+ | stacked | Production, single site |
| Large | 5 | 10+ | stacked or external | Multi-site, high scale |

## Deployment environments
- Connected: public/upstream registries accessible.
- Partially disconnected: intermittent access via transfer station.
- Fully air-gapped: internal mirrors only; no node outbound internet.
- Isolated security zones: DMZ and trusted-zone integration.

## Physical vs virtual architectures
- Bare metal: direct disks for Ceph and etcd, full PCIe/NUMA control; preferred for Ceph at scale and GPU inference.
- VMs: Ceph OSD disks must be raw/SCSI-passthrough (never shared virtual disk); etcd on local SSD with dedicated vCPUs; GPU needs whole-card passthrough.
- Hybrid: mix of bare metal and VMs; hypervisor joins failure domain and must be in DR plan.
