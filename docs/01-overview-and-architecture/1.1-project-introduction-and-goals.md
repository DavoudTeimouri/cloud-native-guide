# 1.1 Project Introduction and Goals

## Purpose and scope
This guide is the authoritative, step-by-step engineering handbook for designing, deploying, operating, troubleshooting, scaling, upgrading, and maintaining an enterprise-grade Cloud-Native infrastructure on premises or in air-gapped environments. It is documentation-as-code, versioned with the infrastructure it describes.

## Project objectives
- Provide a single source of truth for the complete Cloud-Native stack.
- Enable an infrastructure team to go from empty infrastructure to a production-ready platform.
- Every component documented with prerequisites, implementation, validation, security, and troubleshooting.
- Support on-premises, virtualized, hybrid, connected, partially disconnected, and fully air-gapped environments.

## Functional requirements
- Deploy and operate Kubernetes clusters (management and application) via Kubespray.
- Provide load balancing, storage, repositories, registries, GitLab, monitoring, logging, secrets, identity.
- Support air-gapped operation with no node requiring outbound internet at runtime.
- Enable controlled scaling, upgrades, backup, recovery, and maintenance.

## Non-functional requirements
- High availability: stacked etcd, multi-node control plane, pod anti-affinity, LB HA pairs.
- Security: default deny, zero trust, Vault for secrets, image scanning/signing, OIDC/RBAC.
- Automation: Ansible, Kubespray, Argo CD GitOps; idempotent runs.
- Repeatability: inventory-as-source-of-truth, pinned versions with source URLs and check dates.
- Offline operability: internal mirrors for all artifacts; no public dependency at runtime.

## Design principles
- One source of truth per object: Ansible for node state, Kubespray for cluster lifecycle, Argo CD for declared K8s state, Vault for secret values.
- Every version pinned with source URL + check date.
- No secrets in Git; sanitized examples only.
- Destructive actions require explicit confirmation; phases gated by acceptance criteria.

## Target environments and use cases
- On-premises bare metal and virtualized infrastructure.
- Connected, partially disconnected, fully air-gapped, isolated security zones.
- Small, medium, and large deployment scenarios.

## Assumptions and constraints
- Bare-metal or virtualized servers with out-of-band management (IPMI/BMC).
- Internal DNS, NTP, and CA available or deployed as part of Phase 02.
- Operator has administrative access to target hosts and network infrastructure.
- Air-gapped environments rely on internal Harbor, Nexus, GitLab, and Helm mirrors.

## Production readiness criteria
- All control-plane nodes Ready with stacked etcd quorum (3 members).
- Cilium CNI with kube-proxy replacement verified.
- All VERIFIED/PINNED versions from the shared version & compatibility matrix.
- Zero secrets in Git; all alerts route to internal notification (SMTP/Matrix) in air-gap.
- Backup and restore drills executed and RTO/RPO recorded.
