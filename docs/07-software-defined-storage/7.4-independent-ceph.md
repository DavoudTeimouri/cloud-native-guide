# 7.4 Independent Ceph Deployment

## Purpose and scope
Hardware preparation, OS preparation, network design, MON, MGR, OSD, MDS, RGW, CRUSH maps, pools, replication/erasure coding, block/file/object, authentication, encryption, performance tuning, HA, capacity planning.

## Hardware preparation
- 3+ MON nodes (odd, dedicated or co-located)
- OSD nodes: 1+ NVMe/SATA disks per node
- Network: 10GbE+ recommended, separate cluster/public networks if possible

## OS preparation
- Supported Linux distro (see 02-components)
- NTP chrony, firewall open (6789, 3300, 6800-7300, 8080)
- SSH key access for deployment user
- LVM or ceph-volume for OSD provisioning

## Deployment components
- MON: monitor cluster state, quorum
- MGR: monitoring, dashboards, REST API
- OSD: data storage, replication, rebalancing
- MDS: CephFS metadata
- RGW: S3/Swift object storage endpoint

## CRUSH maps & pools
- CRUSH rule: replicate across hosts/racks
- Pools: `.rgw.root`, `.rgw.control`, `.rgw.meta`, `.rgw.log`, k8s pools
- Replication size 3 or erasure coding k=2,m=1

## Authentication & encryption
- cephx authentication
- Client keys: client.admin, client.kubernetes, client.rgw
- Optional: dmcrypt for OSD encryption at rest

## Validation
- `ceph -s` → HEALTH_OK
- All MON in quorum, all OSD up/in
- PGs active+clean
- `rados df` capacity within limits
