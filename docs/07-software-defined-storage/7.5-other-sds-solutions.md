# Other SDS Solutions

## Purpose and scope
Provide equivalent architecture, installation, configuration, integration, and operational documentation for Longhorn and hardware storage appliances as alternatives to Ceph.

## Longhorn
Longhorn is a cloud-native distributed block storage system for Kubernetes. Simpler operational model than Ceph; suitable for smaller-scale application clusters where full Ceph operational complexity is not justified.

- Deployment: Helm chart from internal Helm repository.
- Storage: replica count per volume, node disk selection, storage class.
- Integration: CSI driver, snapshots, backups to S3-compatible target.
- HA: replicas spread across nodes; volume failure tolerance via replica count.

## Hardware storage appliances (SAN/NAS)
- Block: FC or iSCSI LUNs presented as PVs via CSI.
- File: NFS/SMB shares via CSI or flexvolume.
- Object: S3-compatible appliances.
- Integration: CSI driver, multipathing for block, storage classes, snapshots.
- Considerations: vendor lock-in, licensing, support contracts, interoperability with K8s CSI.

## Decision criteria
- Ceph (cephadm): large scale, block/file/object, highest operational complexity.
- Rook-Ceph: K8s-native, medium scale, simpler than cephadm.
- Longhorn: small-to-medium scale, simplest ops, block only.
- Hardware appliance: enterprise block/file/object, highest cost, vendor support.
