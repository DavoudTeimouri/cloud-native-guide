# Bare-metal cloud-init / Kickstart deployment

[Previous step](../storage/ceph/cephadm-deployment.md) | [Next step](../management-cluster/rancher/rancher.md)

---

## A. Purpose and scope

This document describes a fully automated bare-metal provisioning pipeline using **cloud-init** (for Ubuntu/Debian) or **Kickstart** (for RHEL/AlmaLinux/Rocky). The OS baseline, host tuning, and Kubespray inventory are generated from the same answers in this guide — no manual OS install step remains.

The pipeline:

1. **PXE boot** (Kickstart) or **cloud-init user-data** (cloud-init) from an internal mirror
2. **OS baseline** applied via cloud-init/Kickstart + `automation/ansible` playbooks
3. **Kubespray inventory** generated by the guide's bundle scripts
4. **Kubespray run** deploys the Kubernetes cluster

## B. Prerequisites

### Internal infrastructure

| Component | Purpose |
|-----------|---------|
| **Internal HTTP mirror** | Hosts OS images (cloud-init) or Kickstart trees + packages |
| **DHCP + TFTP/HTTP PXE server** | Serves bootloaders and Kickstart configs for Kickstart path |
| **Cloud-init user-data endpoint** | Internal web server serving user-data/meta-data for cloud-init path |
| **IPMI/BMC access** | Power control, serial console, virtual media for bare-metal nodes |
| **Container registry (Harbor/Nexus/OCI)** | Mirrored container images for Kubespray and add-ons |
| **OS package mirror (yum/apt)** | Base OS packages and Kubespray dependencies |

### Node requirements

| Requirement | cloud-init (Ubuntu) | Kickstart (RHEL/Alma/Rocky) |
|-------------|---------------------|------------------------------|
| Boot method | cloud-init NoCloud datasource (HTTP) | PXE boot with Kickstart config |
| Image | cloud-init enabled Ubuntu/Debian image | Minimal install ISO + Kickstart tree |
| Network | DHCP → static IP via user-data | DHCP → static IP via Kickstart |
| Disk | RAID1 boot, dedicated NVMe for Ceph DB/WAL | RAID1 boot, dedicated NVMe for Ceph DB/WAL |

## C. Cloud-init path (Ubuntu/Debian)

### 1. Prepare cloud-init image

```bash
# Download cloud-init enabled Ubuntu image
wget https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
# Or use a local builder (packer) to bake the host baseline into the image
```

Mirror to internal HTTP server:
```bash
# Internal mirror structure
https://mirror.internal/ubuntu/noble/noble-server-cloudimg-amd64.img
```

### 2. User-data template (generated by guide)

The guide generates a `user-data.yaml` per node with:

```yaml
#cloud-config
hostname: k8s-cp-1
fqdn: k8s-cp-1.example.com
manage_etc_hosts: true

users:
  - name: ansible
    sudo: ALL=(ALL) NOPASSWD:ALL
    ssh_authorized_keys:
      - ssh-ed25519 AAAA... ansible@admin

write_files:
  - path: /etc/network/interfaces.d/50-cloud-init.cfg
    content: |
      auto ens1f0
      iface ens1f0 inet static
        address 10.20.0.11/24
        gateway 10.20.0.1
        dns-nameservers 10.10.0.5 10.10.0.6
  - path: /etc/hosts
    content: |
      127.0.0.1 localhost
      10.20.0.11 k8s-cp-1 k8s-cp-1.example.com
      10.20.0.12 k8s-cp-2 k8s-cp-2.example.com
      10.20.0.13 k8s-cp-3 k8s-cp-3.example.com

runcmd:
  - systemctl disable --now ufw
  - apt-get update && apt-get install -y python3-openstackclient
  - reboot
```

### 3. Boot the node

- IPMI virtual media → attach the cloud image
- Set kernel cmdline: `ds=nocloud-net;s=https://user-data.internal/`
- Power on

## D. Kickstart path (RHEL/AlmaLinux/Rocky)

### 1. Prepare Kickstart tree

```bash
# Mirror the full ISO content
mkdir -p /var/www/html/kickstart/rocky9
mount -o loop Rocky-9.4-x86_64-dvd.iso /mnt
rsync -a /mnt/ /var/www/html/kickstart/rocky9/
umount /mnt
```

### 2. Kickstart config (generated by guide)

```bash
# /var/www/html/kickstart/rocky9/ks.cfg
install
url --url=http://mirror.internal/kickstart/rocky9
lang en_US.UTF-8
keyboard us
network --bootproto=dhcp --device=link --activate --hostname=k8s-cp-1
rootpw --lock
user --name=ansible --password=$6$salt$hash --iscrypted --groups=wheel
sshkey --username=ansible "ssh-ed25519 AAAA... ansible@admin"
firewall --disabled
selinux --enforcing
timezone --utc Etc/UTC
bootloader --location=mbr --boot-drive=sda
clearpart --all --initlabel --drives=sda
part /boot --fstype=xfs --size=1024 --ondisk=sda
part / --fstype=xfs --size=1 --grow --ondisk=sda
reboot

%packages
@^minimal-environment
python3
openssh-server
sudo
chrony
%end

%post --log=/var/log/anaconda-post.log
# Host baseline from automation/ansible
rpm -ivh http://mirror.internal/packages/ansible-host-baseline-latest.noarch.rpm
systemctl enable --now chronyd
%end
```

### 3. PXE boot config

```bash
# /var/lib/tftpboot/pxelinux.cfg/default
DEFAULT rocky9
LABEL rocky9
  KERNEL rocky9/vmlinuz
  APPEND initrd=rocky9/initrd.img inst.ks=http://mirror.internal/kickstart/rocky9/ks.cfg ip=dhcp
```

## E. After OS install — Ansible host baseline

Both paths converge here. Run the automation playbooks from the admin host:

```bash
cd automation/ansible
ansible-playbook -i inventory.ini site.yml \
  -e "target_hosts=k8s-cp-1,k8s-cp-2,k8s-cp-3,k8s-w-1,k8s-w-2" \
  -e "registry_host=harbor.internal" \
  -e "ceph_enabled=true"
```

This applies:
- Kernel tuning (sysctl, transparent hugepages, swappiness)
- Container runtime (containerd with registry mirror)
- Ceph prerequisites (if using Ceph)
- SSH keys, sudo, chrony, firewall baseline

## F. Generate Kubespray inventory from guide

```bash
# From the guide repository
python3 scripts/bundle.py --answers answers/example.json --out dist/
cd dist
./deploy.sh --dry-run    # validates inventory
./deploy.sh              # runs kubespray
```

The bundle scripts generate `hosts.ini` and all `group_vars` from the same answers used for cloud-init/Kickstart user-data — no drift.

## G. Version matrix

This method uses the same Kubespray releases as the standard Kubespray path. See `compatibility/version-matrix.md` and the "Kubespray → Kubernetes / etcd" matrix on the Deployment page.

## H. Rollback / re-provision

- **cloud-init**: Re-deploy user-data, reboot node
- **Kickstart**: Reboot node with PXE; Kickstart re-installs cleanly
- **kubespray**: Re-run `deploy.sh`; inventory is idempotent
